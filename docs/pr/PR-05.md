# PR-05: Customer authorization and scoped audit evidence

**Status:** implemented and committed locally; no remote repository or pull request is available.

**Objective:** require an operator-recorded customer authorization for non-demo CI exports and deliveries, scoped to the same tenant, repository, and review window.

**Files changed:** `company_os/api.py`, `company_os/authorization.py`, `company_os/db.py`, `company_os/jobs.py`, `company_os/schema.py`, `company_os/worker.py`, `migrations/versions/0001_initial.py`, `migrations/versions/0002_customer_authorizations.py`, `tests/test_cli.py`, `tests/test_jobs_agents.py`, README and architecture, acceptance, implementation, threat-model and evidence documents.

**Architecture:** revision 0002 adds a persistent authorization record with repository, reviewed date window, authorization-document digest, operator, expiry, and revocation state. The API checks scope at engineering-job submission. The worker checks it again before processing so expiry or revocation after enqueue blocks work. Delivery evidence records the authorization reference and scope digest. Synthetic operator-demo inputs remain explicitly marked as demos.

**Migration impact:** additive Alembic revision `0002` follows `0001`. The initial revision now freezes its original table set so later metadata additions do not change its behavior. A migration test upgrades a legacy 0001 database to head. Downgrade drops only the authorization table; take and verify a database backup before rollback because authorization records would be lost.

**Security impact:** non-demo engineering and delivery fail closed without an active, matching, same-tenant authorization. Writes and revocation require the operator role. The operator attests they reviewed the customer-signed authorization and stores its SHA-256 digest; the application does not verify the customer's signature or identity. This is not proof that any customer authorization was obtained.

**Automated tests and evidence:** Ruff passed; mypy passed with no issues in 16 source files; `pytest -q tests` reported 28 passed with one Starlette/httpx deprecation warning. Tests cover additive migration, scope/tenant checks, expiry, revocation, and delivery evidence linkage. A throwaway PostgreSQL Compose stack migrated through 0002; `/health` returned `ok`, `/ready` succeeded, then containers/network/volume and generated `.env` were removed. Exact commands are in `../evidence/local-implementation-tests.md`.

**Known limitations:** local token identity only; no verification of customer identity or authorization signature; no real customer data or pilot; existing sandbox, production authentication, provider, and external delivery limitations remain.

**Acceptance:** missing, cross-tenant, mismatched, expired, and revoked authorization blocks non-demo engineering work; a completed delivery records the matching authorization reference and scope digest. Demo evidence is labeled `DEMO_ONLY`.

**Rollback:** stop services, back up the database, then downgrade from `0002` to `0001` only if losing authorization records is acceptable. Reverting application code without the migration downgrade keeps the extra table harmless. No external effect or customer communication is involved.
