# PR-02: Local application foundation and offline vertical slice

**Status:** implemented locally; not opened remotely.

**Objective:** provide a runnable local Python service with SQL persistence, tenant-scoped authentication, durable jobs, signed event ingestion, five offline workflows, cost records, evidence and an operator dashboard.

**Files:** `pyproject.toml`, `.env.example`, `alembic.ini`, `migrations/`, `company_os/`, `tests/`.

**Architecture:** modular monolith; SQLAlchemy Core and one Alembic schema; SQLite by default and PostgreSQL URL support. Job/outbox/evidence records share one transaction authority. The optional MIT CFO package uses its pinned read-only analyzer contract; fallback mode is identified. No source is vendored.

**Migration impact:** initial revision `0001` creates all current tables; downgrade drops all tables. Back up state before any downgrade.

**Security impact:** generated local operator token is represented in config by SHA-256; reader/member/operator checks; tenant predicates; HMAC webhook; scoped, expiring, digest-bound approval; common token redaction before task persistence. Production configuration fails closed. No external effects are dispatched.

**Automated tests:** `tests/test_cli.py`, `tests/test_foundation.py`, `tests/test_jobs_agents.py`.

**Evidence:** Python 3.12 local venv, `25 passed`; Ruff and mypy passed. The optional CFO package was installed from ignored audited checkout revision `f7b6cf2e65b3d2ef3f15cecb4fc1c65874c3f56f`; tests passed with adapter active. Starlette/httpx emitted one deprecation warning. Exact local evidence is in `../evidence/local-implementation-tests.md`; Phase 0 evidence is in `../evidence/phase0-tests.md`.

**Known limitations:** no live AI provider, GitHub retrieval/write, independent financial verification, provider cost, external effect sender, process-kill fault injection, full tenant/API security fuzzing, PostgreSQL smoke test, or production identity. Application-level concurrency is one worker process. See `../ACCEPTANCE.md`.

**Acceptance:** local migration/readiness, auth denial, five offline jobs, evidence/evaluation, approval negative paths, webhook dedupe, lease recovery, cost cap, and Ruff are covered by executed checks above.

**Rollback:** stop local services, back up the database, revert the application revision; only downgrade `0001` when intentionally deleting all local state. Compose/database recovery guidance is in `../RECOVERY.md`.
