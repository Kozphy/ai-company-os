# PR-06: EvalForge artifact import boundary

**Status:** implemented locally; no remote repository or pull request is available.

**Objective:** allow an operator to attach a compact EvalForge export summary to an existing tenant-owned job while preserving the proprietary source boundary and keeping local deterministic evaluation authoritative.

**Files changed:** `company_os/evalforge_import.py`, `company_os/api.py`, `tests/test_evalforge_import.py`, implementation/gap/acceptance docs and local test evidence.

**Architecture:** operator-only API accepts the EvalForge JSON export shape observed in `.audit/EvalForge/app/export_service.py` at audited revision `4fcec3bc4fa816a533d3445ebc3dc82d38871659`. The importer checks the pinned revision string and basic structure, stores a SHA-256 digest plus counts, and omits raw prompts and responses. Imported content is untrusted: its source revision is caller-asserted, its state is `UNVERIFIED_IMPORTED`, and its decision is always `REVIEW_ONLY`. It cannot change the job or OS deterministic result. Repeated import of identical bytes for the same tenant/job is idempotent.

**Migration impact:** none; it uses the existing evaluations table.

**Security impact:** authenticated operator only, tenant-scoped target job lookup, body-limited request and no raw artifact persistence. Imported claims are not cryptographically authenticated, and source version is not independently proven.

**Automated tests and evidence:** Ruff passed; mypy reported no issues in 17 source files; `pytest -q tests` reported 31 passed with one Starlette/httpx deprecation warning. Tests cover shape/revision rejection, role and tenant checks, idempotent storage, and unchanged queued job state after an import with a reported failure. See `../evidence/local-implementation-tests.md`.

**Known limitations:** only the JSON export shape is supported; no EvalForge server is exposed or called; caller-supplied source revision is not attested; no evaluation metric or model quality is independently reproduced.

**Acceptance:** a valid pinned-shape export can be attached to an owned job as review-only evidence; malformed or other-revision input is rejected; imported verdicts never override local deterministic gates.

**Rollback:** revert the endpoint/parser. No migration is required; remove imported rows from `evaluations` only after backup and tenant/job scoping review.
